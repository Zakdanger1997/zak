# 🤖 نسخة الوكيل المستقل (AI Agent) — بديلة عن الـ5 workflows

بدل الأنابيب الثابتة (node بعد node)، هنا **وكيل ذكاء اصطناعي واحد** يقود العملية بنفسه: يجلب العملاء، يقرّر ماذا يكتب، يرسل، ويمنع التكرار — عبر **أدوات (Tools)** موصولة به.

## ⚠️ اقرأ هذا أولاً (مهم)

- إعطاء وكيل حرية إرسال إيميلات حقيقية **قوي لكنه أكثر خطورة** من الأنابيب الثابتة. لذلك:
- **الأمان مفروض داخل الأدوات، لا في عقل الوكيل:** أداة `send_email` **ترفض** أي تكرار أو تجاوز للحد اليومي مهما قرّر الوكيل. فحتى لو أخطأ الوكيل، لا يمكنه الإرسال مرتين أو تجاوز 40/يوم.
- **جرّبه في وضع آمن أولاً** (بحدّ 2–3 وأرسل لنفسك) قبل الإطلاق الحقيقي.
- النسخة الثابتة (مجلد `workflows/`) تبقى **بديلاً موثوقاً** إن أردت الرجوع إليها.

## المكوّنات (3 ملفات)

| الملف | الدور |
|---|---|
| `00_autonomous_agent.json` | الوكيل الرئيسي: جدول → AI Agent (نموذج + ذاكرة + أدوات) → تقرير |
| `tool_get_contacts.json` | أداة: تُعيد العملاء غير المُرسَل لهم لحساب/منطقة |
| `tool_send_email.json` | أداة: ترسل إيميلاً واحداً وتفرض منع التكرار + الحد + تسجّل |

## كيف يعمل الوكيل؟

```
جدول (كل ساعة عمل)
   → الوكيل يقرأ تعليماته (SOP): "لكل حساب، اجلب العملاء واكتب وأرسل"
   → لكل حساب: يستدعي get_pending_contacts(account, region)
   → لكل عميل: يكتب إيميلاً شخصياً ثم يستدعي send_email(...)
        └─ أداة send_email: تتحقق (تكرار؟ حد؟) → ترسل عبر SMTP الصحيح → تسجّل
   → في النهاية: يكتب ملخصاً ويُرسله إلى إيميلك الأساسي
```

## خطوات التركيب (بعد تركيب n8n وd docker من الدليل الأساسي)

1. **استورد الملفات الثلاثة** في n8n.
2. **اربط الاعتمادات:** `OpenAI`، و `SMTP account1..5` (نفس أسماء النسخة الثابتة).
3. **⚠️ اربط الأدوات بالـ sub-workflows (خطوة إلزامية):**
   - في `00_autonomous_agent.json`، افتح عقدة `get_pending_contacts` → في خانة Workflow اختر workflow المسمّى **TOOL — get_pending_contacts**.
   - افتح عقدة `send_email` → اختر **TOOL — send_email**.
   - (القيم `REPLACE_..._ID` أماكن تعبئة — لأن معرّفات الـ workflow تُنشأ عند الاستيراد.)
4. **عدّل عقدة `قراءة الطلب`** داخل `tool_send_email` → ضع عناوين المرسِل الحقيقية في كائن `FROM` (بدل `BURAYA_..._EMAIL`) وغيّر `DAILY_LIMIT` إن أردت.
5. **عدّل الـ SOP** في عقدة `الوكيل`: صحّح خريطة الحسابات↔المناطق لتطابق `master-list.csv`.
6. **عدّل `main_email`** في عقدة `ابدأ الدورة` (لاستقبال التقرير).
7. تأكد أن `data/master-list.csv` و `signatures.csv` وسجلات الحسابات موجودة (كما في النسخة الثابتة).

## اختبار آمن قبل الإطلاق

1. في `tool_send_email` اجعل `DAILY_LIMIT = 2` مؤقتاً.
2. ضع إيميلك الشخصي في `master-list.csv` بمنطقة account1.
3. شغّل `00_autonomous_agent` يدوياً (**Execute Workflow**).
4. تأكد أن الرسالة وصلتك، والتوقيع ظهر، وأن التقرير وصل إيميلك.
5. أعد الحد إلى 40 وفعّل الجدولة.

## عن جلب العملاء تلقائياً (Find leads)

الوكيل حالياً يجلب العملاء من `master-list.csv`. **الجلب الآلي الحقيقي** (اكتشاف شركات جديدة) يحتاج **مصدر بيانات** مثل Apollo أو Hunter عبر API. هذا غير مضمّن لأنه يتطلب مفتاح API ومصدرك. عند جاهزيتك أضيف أداة `find_leads` (عقدة HTTP Request Tool إلى Apollo) تُغذّي القائمة تلقائياً قبل الإرسال — أخبرني بالمصدر ومفتاحه وأربطها.

## النموذج والتكلفة

- يستخدم `gpt-4o` (أفضل في استخدام الأدوات). للتوفير يمكن تغييره إلى `gpt-4o-mini` في عقدة «نموذج OpenAI».
- الوكيل يستهلك توكنات أكثر من النسخة الثابتة (تفكير + استدعاء أدوات) — طبيعي لأسلوب الوكلاء.
